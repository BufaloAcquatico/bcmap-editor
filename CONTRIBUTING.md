# Contributing to BCMap Editor

This covers the developer workflow. For what the editor is and how to use
it, see [README.md](README.md).

## Prerequisites

- Node 22 (see `.node-version`; the package requires `>=20`)
- pnpm (`pnpm install` for dependencies)

## Build

```bash
# Install dependencies
pnpm install

# Build (typecheck + embed JS in map-editor.html + regenerate README tables)
npm run build

# Watch-compile only (does NOT re-embed: changes reach the page only
# through npm run build, then a hard refresh)
npm run dev
```

## Tuning motion

All animation durations live in `src/anim.ts` (`MOTION_MS` and
`MOTION_QUICK_MS`); canvas loops, CSS transitions, fades and tests all
derive from them, so retuning those two constants retunes everything.
Source edits only reach the page through a rebuild: run `npm run build`
after changing values, then hard-refresh (note: `npm run dev` compiles
without re-embedding, so it alone changes nothing visible). The live
tuning prints one `Motion durations: …` line to the devtools console on
every load — check there first if a retune seems to do nothing.

## Assets

```bash
# Download assets (drives from the shared catalog, with throttling)
npm run download-assets

# Options: skip existing files by default; add --force to re-download
#   --force            re-download every asset
#   --concurrency=N    parallel requests (default 2)
#   --delay=MS         delay between requests (default 150)
#   --retries=N        retries per asset (default 3)
```

The catalog in `src/catalog.ts` is the single source of truth: pickers,
renderer, importer, and this script all read it, so a game addition
surfaces everywhere. If the game publishes new items, add them to the
catalog and re-run the downloader; if the asset server 404s brand-new
files, they render as color-fallback placeholders until the server
publishes them.

## Formatting

Prettier, 4-space indent:

```bash
npm run format
npm run format:check
```

## Tests

```bash
# Unit tests
npm test

# E2E tests (requires Playwright browsers)
npm run test:e2e

# E2E tests in Docker (no local browser install needed)
npm run test:e2e:docker

# Unit tests in Docker
npm run test:e2e:docker:unit
```

### Docker testing (recommended for Fedora/Linux)

Runs Playwright E2E tests without installing browsers locally.

**Requirements:** Docker and Docker Compose installed

```bash
# Build and run E2E tests
docker compose -f docker-compose.test.yml up --build --abort-on-container-exit test

# Or use npm script
npm run test:e2e:docker

# Run unit tests in Docker
npm run test:e2e:docker:unit
```

**Files:**

- `Dockerfile.test` - Test image based on `mcr.microsoft.com/playwright:v1.64.0-jammy`
- `docker-compose.test.yml` - Compose file with volume mounts for fast iteration

## Technical notes

- TypeScript → compiled and embedded in `map-editor.html`
- Canvas 2D rendering with image caching
- Bootstrap 5 for UI (vendored, offline-safe)
- LZString for map-code compression
- Vitest (unit) + Playwright (E2E) for testing
- The Controls and Commands tables in the README are generated by
  `scripts/render-keybinds-doc.js` during `npm run build` — edit the
  keybind/command registries in `src/`, never the tables by hand.
